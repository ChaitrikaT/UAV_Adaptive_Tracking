5-Stage Condition-Aware Perception Pipeline

How each frame is processed online without future information or ground-truth leakage.

Stage 1 • Input
Video Frame Decode
Reads sequential RGB frame from recorded air-to-air UAV video.
→
Stage 2 • Feature Extraction
10 Online Condition Cues
Global scene stats (brightness, contrast, sharpness, frame diff) + prior track state (target size, speed, last confidence, frames unseen).
→
Stage 3 • Difficulty Model
Logistic Miss Predictor
Outputs a continuous difficulty score [0, 1] estimating the probability that 640 px YOLO will fail to detect the target.
→
Stage 4 • Adaptive Switch
Threshold Controller (τ)
If score ≥ τ, selects ROBUST (960 px) for higher small-object sensitivity; otherwise selects FAST (640 px).
→
Stage 5 • Detection & ID
YOLO11n + ID Tracker
Runs YOLO at the chosen resolution and associates boxes across frames using IoU matching and track aging.

How to Read These Metrics

Track Recall & Precision Percentage of ground-truth drone boxes successfully tracked (IoU ≥ 0.50) and percentage of predicted boxes that match a real drone.
IDF1 (Identity F1 Score) Measures how consistently the tracker keeps the same ID number on a drone over time rather than dropping or swapping IDs.
MOTA (Multi-Object Tracking Accuracy) Combines misses (FN), false alarms (FP), and ID switches: 1 - (FN + FP + IDSW) / GT. Can be negative when false alarms + misses exceed ground-truth boxes.
ROBUST Frac & Cost (ms/frame) Fraction of frames routed to 960 px ROBUST mode and total end-to-end processing time per frame (including video decode and tracking).

Summary of Experimental Findings & Technical Explanations

Key engineering takeaways explaining both the strengths of the system architecture and the honest empirical limits observed on real air-to-air footage.

1. Why is MOTA negative across all policies?

MOTA is calculated as 1 - (Missed Targets + False Positives + ID Switches) / Ground Truth Boxes. When tracking tiny 10–17 pixel drones against cluttered backgrounds, lowering confidence thresholds to catch small objects introduces false positives alongside missed frames. Whenever FN + FP + IDSW exceeds the number of ground-truth boxes, MOTA becomes mathematically negative. Reporting IDF1, precision, recall, and ID switches alongside MOTA gives a complete picture.

2. Why did FAST (640 px) and ROBUST (960 px) take the same time (~34 ms) on the test hardware?

On a dedicated GPU, parallel tensor cores are under-utilized at small batch sizes, so processing a 960×960 tensor takes nearly the same wall-clock time as 640×640. Consequently, adaptive switching could not yield a GPU latency speedup here. On CPU-only or embedded edge processors (such as Raspberry Pi or Jetson Nano), 960 px inference requires 2.25× more pixel operations, where dynamic switching directly saves compute.

3. Why did the adaptive policy choose ROBUST mode 98–99% of the time?

Because the lightweight YOLO11n detector missed 63%–93% of tiny drones in FAST mode on the validation clips, the calibrated logistic model predicted a high miss probability on almost every frame, keeping the difficulty score above the switching threshold τ to protect tracking recall.

4. Why did Test Clip 10 record 0% recall, and how was it verified?

To rule out annotation offsets or timestamp bugs, we evaluated temporal shifts from k = -5 to +5 frames and visually inspected clip10_full_frames.png. Recall peaks cleanly at k = 0 on Clips 7–9, and Clip 10's green boxes sit accurately on real distant drones—confirming a genuine domain generalization gap for a 12-epoch detector rather than a pipeline bug.

5. How was experimental integrity protected against data leakage?

All tracker thresholds were tuned exclusively on Clip 7 and frozen before evaluation; offline cache replay was verified to match true online frame-by-frame execution with 0 mismatches; and the reserved test set (Clips 9–10) was executed strictly once without post-hoc parameter tuning.
